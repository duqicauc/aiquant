# 基本面筛选逻辑问题分析

## 发现的问题

### 1. ✅ 数据单位确认（已确认正确）

- **市值（total_mv）**：单位是"万元" ✓
- **营业收入（revenue）**：单位是"元" ✓
- **净利润（n_income）**：单位是"元" ✓
- **ROE**：单位是百分比（%） ✓
- **ROA**：单位是百分比（%） ✓

### 2. ⚠️ 筛选条件可能太宽松

#### 问题1：ROE>0 和 ROA>0 太宽松

**当前设置**：
- ROE>0
- ROA>0

**问题**：
- 对于"被错杀的优质公司"，ROE和ROA应该设置更高的阈值
- ROE>0只要求盈利，但优质公司应该有更好的盈利能力

**建议**：
- ROE>3% 或 5%（根据市场情况调整）
- ROA>2% 或 3%（根据市场情况调整）

#### 问题2：净利润>200万可能偏低

**当前设置**：
- 净利润>200万（单位：元）

**问题**：
- 对于市值10-100亿的公司，净利润>200万可能太宽松
- 如果市值是10亿，净利润200万，ROE只有0.2%，这不算优质公司

**建议**：
- 净利润>500万 或 1000万
- 或者根据市值动态调整：净利润>市值*0.01（即ROE>1%）

#### 问题3：营业收入>1亿可能偏低

**当前设置**：
- 营业收入>1亿（单位：元）

**问题**：
- 对于市值10-100亿的公司，营业收入>1亿可能偏低
- 如果市值是100亿，营业收入1亿，市销率100倍，这不算优质公司

**建议**：
- 营业收入>5亿 或 10亿
- 或者根据市值动态调整：营业收入>市值*0.1（即市销率<10倍）

### 3. ⚠️ 数据获取逻辑问题

#### 问题1：财务数据按报告期发布，不是按交易日期

**当前实现**：
- 使用`start_date`和`end_date`获取最近一年的财务数据
- 然后选择最新的报告期数据

**问题**：
- 财务报告有延迟，最新报告期可能不是当前日期
- 应该明确获取最新报告期的数据，而不是按交易日期

**建议**：
- 获取最近一年的财务数据，然后选择最新的报告期（end_date最大的）
- 或者使用`period`参数直接指定报告期（但需要知道最新报告期）

#### 问题2：没有处理数据缺失情况

**当前实现**：
- 如果财务数据缺失，返回None，股票被标记为未通过

**问题**：
- 某些股票可能财务数据暂时缺失，但不代表基本面不好
- 应该区分"数据缺失"和"数据不达标"

**建议**：
- 对于数据缺失的股票，可以标记为"数据缺失"，但不一定直接过滤
- 或者提供选项：是否过滤数据缺失的股票

### 4. ⚠️ 性能问题

#### 问题1：对每只股票单独调用API

**当前实现**：
- 在`screen_stocks`方法中，对每只股票单独调用`get_latest_financial_data`
- 每个股票需要调用3次API（daily_basic、fina_indicator、income）

**问题**：
- 如果筛选500只股票，需要调用1500次API
- 效率很低，而且可能触发限流

**建议**：
- 批量获取财务数据
- 使用缓存机制
- 考虑使用多线程或异步请求

### 5. ⚠️ 筛选逻辑问题

#### 问题1：市值筛选使用总市值还是流通市值？

**当前实现**：
- 使用`total_mv`（总市值）

**问题**：
- 对于筛选"被错杀的优质公司"，应该使用流通市值还是总市值？
- 流通市值更能反映市场真实情况

**建议**：
- 考虑使用`circ_mv`（流通市值）进行筛选
- 或者同时考虑总市值和流通市值

## 建议的改进方案

### 方案1：提高筛选阈值（推荐）

```python
config = {
    'market_cap_min': 100000,      # 10亿
    'market_cap_max': 1000000,     # 100亿
    'revenue_min': 5e8,            # 营业收入>5亿（提高）
    'net_profit_min': 5000000,     # 净利润>500万（提高）
    'roe_min': 3,                  # ROE>3%（提高）
    'roa_min': 2,                  # ROA>2%（提高）
}
```

### 方案2：根据市值动态调整阈值

```python
# 根据市值动态计算阈值
market_cap = fina_data.get('market_cap', 0)  # 万元

# 动态阈值
revenue_min = market_cap * 0.1  # 营业收入>市值*10%（市销率<10）
net_profit_min = market_cap * 0.01  # 净利润>市值*1%（ROE>1%）
```

### 方案3：使用流通市值

```python
# 使用流通市值而不是总市值
market_cap = latest_basic.get('circ_mv', 0)  # 流通市值（万元）
```

## 总结

主要问题：
1. ✅ 数据单位正确
2. ⚠️ 筛选条件可能太宽松（ROE>0、ROA>0、净利润>200万）
3. ⚠️ 财务数据获取逻辑需要优化（明确按报告期获取）
4. ⚠️ 性能问题（单独调用API）
5. ⚠️ 市值筛选使用总市值还是流通市值需要明确

建议优先修复：
1. 提高ROE和ROA的阈值（ROE>3%，ROA>2%）
2. 提高净利润阈值（净利润>500万或1000万）
3. 明确财务数据获取逻辑（按报告期获取最新数据）
