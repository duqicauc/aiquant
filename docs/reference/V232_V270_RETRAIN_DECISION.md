# v232 / v270 是否需要重新训练 — 评估与决策指南

本文档从**是否重训**的角度，说明如何用现有数据与脚本做判断，以及满足什么条件才建议重训。

---

## 一、结论先行（如何判断）

| 情况 | 建议 |
|------|------|
| **训练/测试集指标正常**（AUC≥0.65，Top10 胜率 45%～55%）且 **近期 Top10 表现正常** | **暂不重训**，优先做集成与策略优化 |
| **训练集指标差**（AUC&lt;0.60 或 F1 明显下降） | **需要重训**，先查特征/标签/泄漏再重训 |
| **近期 Top10 表现持续差**（胜率&lt;40% 或平均收益明显为负） | **考虑重训或校准**，并检查市场是否发生结构性变化 |
| **概率严重失准**（高概率组实际涨幅远低于预期） | **先做校准或重训**，视情况选择 |

下面分别说 v232、v270 各自要看什么、怎么查。

---

## 二、v2.7.0 模型

### 2.1 训练时保存的指标（最直接）

训练脚本 `scripts/train_v270_model.py` 会在保存模型时写入：

- 路径：`data/models/breakout_launch_scorer/versions/v2.7.0/metadata.json`
- 内容示例：`metrics.auc`、`metrics.precision`、`metrics.recall`、`metrics.f1`（均为测试集上的结果）

**如何查看**（在项目根目录）：

```bash
cat data/models/breakout_launch_scorer/versions/v2.7.0/metadata.json
```

若该文件不存在，说明当前环境从未跑过 v2.7.0 训练，或模型目录未纳入版本管理，需要**重新跑一次训练**才能得到这批指标。

**判断标准**：

- **AUC ≥ 0.65**：可接受，不必仅为指标重训。
- **AUC &lt; 0.60**：建议排查（特征、标签、时间泄漏），然后重训。
- **AUC 0.60～0.65**：边界区，结合「近期 Top10 表现」再定；若 Top10 胜率正常可暂不重训。

### 2.2 近期预测表现（真实表现）

用**最近一段时间**的预测结果 + 实际行情，看 Top10 在固定持有期（如 5 日、10 日）的胜率与平均收益。

**脚本**：`scripts/evaluate_v232_v270_20260105_20260303.py`
**逻辑**：对每个预测日，从 `v270_ensemble_all_YYYYMMDD.csv` 按 `probability` 取 Top10，以预测日收盘价为买入价、T+5/T+10 收盘价为卖出价，算收益率并汇总。
**依赖**：DataManager + 行情接口（如 Tushare），需在本地有依赖的环境下运行：

```bash
python scripts/evaluate_v232_v270_20260105_20260303.py
```

**判断标准**：

- **Top10 胜率 45%～55%**：正常，无需因胜率重训。
- **Top10 胜率 &lt; 40%**：偏弱，可考虑重训或加强特征/样本。
- **Top10 平均收益**：建议与同期指数对比；若明显跑输且持续多周，再考虑重训。

### 2.3 小结：v2.7.0 重训决策

1. 若有 `metadata.json`：先看 AUC；≥0.65 则训练集侧可接受。
2. 再跑 `evaluate_v232_v270_20260105_20260303.py` 看 1～3 月 Top10 胜率与收益。
3. **两者都正常** → 不需要重训，优先做策略/集成优化。
4. **训练集指标差** → 需要重训。
5. **仅近期表现差** → 先看是否市场风格变化或数据问题，再决定是重训还是只调策略。

## 三、v2.3.2 模型

### 3.1 底层模型是 v2.3.0

v2.3.2 的预测脚本用的是 **v2.3.0** 的模型文件（XGBoost + 校准器），v2.3.2 只是在预测阶段做了 `final_score`（RSI、涨停、penalty 等）后处理，**没有单独的 v2.3.2 训练产物**。

因此「v232 要不要重训」等价于：**底层 v2.3.0 要不要重训**，以及**后处理规则要不要改**。

### 3.2 训练时保存的指标（v2.3.0）

- 路径：`data/models/breakout_launch_scorer/versions/v2.3.0/metadata.json`
- 由 `scripts/train_v23_model.py` 在训练时写入，字段与 v2.7.0 类似（AUC、precision、recall、F1）。

**如何查看**：

```bash
cat data/models/breakout_launch_scorer/versions/v2.3.0/metadata.json
```

**判断标准**：与 v2.7.0 相同，AUC≥0.65 可接受，&lt;0.60 建议重训。

### 3.3 近期预测表现（v2.3.2 的 Top10）

同样用「预测日 + 实际行情」做固定持有期收益评估。

**数据**：`v2.3.2_top10_YYYYMMDD.csv`（已是 Top10）。
**脚本**：同上 `evaluate_v232_v270_20260105_20260303.py`，内部会分别加载 v232 Top10 和 v270 Top10，输出按模型汇总的胜率与平均收益。

**判断标准**：与 v2.7.0 一致，Top10 胜率 45%～55% 视为正常，&lt;40% 考虑重训或校准。

### 3.4 互补策略里 v232 几乎没被用到

当前回测中，被卖出的标的中来自 v2.3.2 的只有极少数（例如 1 笔），原因是互补策略里 v232 评分被 v270 压制。因此：

- **按来源统计**的「v232 表现」样本太少，**不能**作为是否重训 v232 的依据。
- 要判断 v232 是否该重训，必须看 **v2.3.2 单独 Top10** 的近期表现（即上文的 Top10 固定持有期评估）。

### 3.5 小结：v2.3.2 / v2.3.0 重训决策

1. 若有 v2.3.0 的 `metadata.json`：先看 AUC 是否 ≥0.65。
2. 跑 `evaluate_v232_v270_20260105_20260303.py`，看 **v2.3.2** 在 1～3 月 Top10 的胜率与平均收益。
3. **训练集指标正常 且 Top10 表现正常** → 不需要重训 v2.3.0；若希望 v232 在互补里更有用，优先**修互补策略的评分尺度**（见《V232_V270_OPTIMIZATION_AND_EVALUATION》），而不是先重训。
4. **训练集指标差 或 Top10 持续偏弱** → 考虑重训 v2.3.0（或后续版本），并可同时输出与 v270 同尺度的校准概率，便于集成。

## 四、推荐执行顺序（用于「是否重训」）

| 步骤 | 动作 | 目的 |
|------|------|------|
| 1 | 查看 `data/models/.../v2.3.0/metadata.json` 和 `.../v2.7.0/metadata.json` 是否存在及 AUC 等 | 判断训练/测试集分类能力是否在可接受范围 |
| 2 | 在本地运行 `python scripts/evaluate_v232_v270_20260105_20260303.py` | 得到两模型在 1/5～3/3 的 Top10 胜率与平均收益（5 日/10 日） |
| 3 | 对照上文「判断标准」：AUC、Top10 胜率、平均收益 | 做出「暂不重训 / 需要重训 / 先校准或调策略」的结论 |
| 4 | 若暂不重训 | 优先做互补策略评分修复、冷却期、分层卖出等（见优化文档） |
| 5 | 若需重训 | 用当前 `train_v23_model.py` / `train_v270_model.py` 重训，并保存新的 metadata，便于日后对比 |

---

## 五、若没有 metadata 或无法跑行情接口

- **没有 metadata**：只能通过「重新跑一次训练」得到 AUC 等；或从历史训练日志里找当时的测试集指标。
- **无法跑带行情接口的评估脚本**：可用「按来源统计」作为参考（`evaluate_v232_v270_from_backtest_csv.py`），但当前 v232 来源样本极少，**不能单独据此决定 v232 是否重训**；v270 的来源统计可作辅助（胜率 41%、总盈亏为正说明策略下 v270 仍有贡献）。
